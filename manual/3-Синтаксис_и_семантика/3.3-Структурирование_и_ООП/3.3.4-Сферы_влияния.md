# Сферы влияния (scopes) {#сферы-влияния}

Всё внутри движка делится по так называемой [Scoping system](https://zdoom.org/wiki/Object_scopes_and_versions) — по "сферам влияния" или "сферам деятельности", то есть принадлежности либо к геймплею/миру, либо к интерфейсу, либо к категории других данных.

Суть этого разделения в том, чтобы обезопасить доступ из разных концов движка друг к другу — ради синхронизации в мультиплеере и в записанных демо.


## Игровой мир и геймплей: play {#play}

Любой объект непосредственно игрового мира — актор, Thinker, LineTracer и так далее.

Синтаксис объявления для класса:

```CPP
class Something play {
    // ...
}
```

Синтаксис объявления для методов (_уточнить: кейворд можно ставить и до, и после объявления?_):

```CPP
play void Something() {
    // ...
}
```

Наследовать от класса, принадлежащего игровому миру, класс другой области влияния нельзя.



## Интерфейс: ui {#ui}

Любой объект интерфейса (в том числе графического) и в целом мета-взаимодействия с игрой. Не записывается в демо-файлы и не передаётся кому-либо в мультплеере.

Синтаксис объявления для класса:
```CPP
class Something ui {
    // Интерфейсный класс.
}
```

Синтаксис объявления для методов (_уточнить: кейворд можно ставить и до, и после объявления?_):

```CPP
ui void Something() {
    // ...
}
```

Также, как и в `play`, изменить область влияния при наследовании нельзя.


## Нейтральные данные: data {#data}

Всё, что не относится ни к `play`, ни к `ui`; просто некие нейтральные данные, не относящиеся ни к одной из категорий.

Любой класс и любая структура, не наследованная от `play` или `ui`, по умолчанию принадлежит сфере влияния данных — поэтому ключевого слова назначения для классов и структур нет. От данных можно наследовать классы в другие сферы влияния — и в `play`, и в `ui`.

Сбросить до "нейтральных данных" сферу можно только для методов ("очищением" предыдущей назначенной области влияния):

```CPP
clearscope void Something() {
    // ...
}
```


## Таблица взаимодействий {#таблица-взаимодействий}

Если не указано чего-либо иного явно, то все методы внутри класса с модификатором "`play`" будут относиться к игровому миру; все методы внутри класса с модификатором "`ui`" — к интерфейсу; все методы в классах без модификаторов — соответственно, к данным.

Далее представлена таблица возможности взаимодействия разных сфер влияния друг с другом. При "Полном доступе" можно делать с целевым объектом всё, что может осуществить язык: читать и записывать в переменные, вызывать методы, вызывать конструкторы. Если стоит "Только чтение" — можно только считывать переменные, без записи в них и без возможности вызова методов.

|                | …Вызывается `play` |  …Вызывается `ui`  | …Вызывается `data` |
|---------------:|:------------------:|:------------------:|:------------------:|
| Из-под `play`… | **Полный доступ**  | -                  | **Полный доступ**  |
|   Из-под `ui`… | _Только чтение_    | **Полный доступ**  | **Полный доступ**  |
| Из-под `data`… | _Только чтение_    | -                  | **Полный доступ**  |

Из-под `play`:

* Можно свободно читать/записывать и в `play`, и в `data`;
* Не удастся сделать что-либо с интерфейсной частью (например, нельзя записать CVar с помощью выстрела).

Из-под `ui`:

* Свободное чтение/запись в `ui` и в `data`;
* Можно только видеть игровую вселенную (так, можно получить количество патронов для вывода в статусбар, но не поменять их).

Из-под `data`:

* Нет ограничений на чтение/запись в свою область влияния — в `data`;
* Можно только считывать данные с игрового мира.
* `ui` недоступен вовсе.

Также невозможно создавать классы другой сферы влияния, если у той сферы нет доступа на запись (к примеру, нельзя создать `play` из-под `ui`).

В GZDoom 4.11.0 было введено [ключевое слово `unsafe(...)`](3.3.6-Модификаторы_переменных_и_методов.md), позволяющее "легитимно" нарушать границы областей влияния. **Используйте только во время отладки!** Некорректное использование `unsafe(...)` может оказаться практически неотслеживаемым, а также привести к рассинхронизации в демо и мультиплеере, к вылету движка и к другим неприятным последствиям!
