# Наследование, полиморфизм, области видимости, статические методы

## Три парадигмы ООП

ZScript является объектно-ориентированным языком, и из ООП на него распространяются и [парадигмы](https://www.insight-it.ru/theory/2008/tri-osnovnyx-komponenta-paradigmy-obektno-orientirovannogo-programmirovaniya/):

* Наследование: использование одного класса в качестве "родителя" другого, с сохранением в дочернем классе свойств (переменных, методов) родительского, но и с добавлением своих. С помощью данной парадигмы выстраиваются целые иерархии и деревья классов — довольно удобно.
* Полиморфизм: возможность изменять некоторые свойства родителей в дочерних классах. Даёт бóльшую гибкость иерархии.
* Инкапсуляция: обеспечение принципа "вещи-в-себе" — цельности объекта по данным и коду; также предоставляет полуавтоматическую защиту от несанкционированного доступа ("кто и как может работать со мной").

Наследование — возможность создавать классы с сохранением свойств какого-то другого класса. Обозначается двоеточием и названием родительского класса перед открывающей операторной скобкой класса:

```Csharp
class A {
    int a, b;
    String internalstr;

    void PrintStr( void ) {
        console.printf( internalstr );
    }
}

class B1: A {
    // Здесь есть и поля "a", "b", "internalstr", и метод "PrintStr".
    // Добавляем ещё что-нибудь:
    double gravityValue;
}

class C1: B1 {
    // Наледованы поля "a", "b", "internalstr", "gravityValue" и метод "PrintStr".
    int sum4( int c ) {
        return a + b + c;
    }

    double AdjustGravity( void ) {
        if ( gravityValue < 0.0 )
            gravityValue = 0.0;

        return gravityValue;
    }
}

class B2: A {
    // Тут нет полей и методов из B1 и C1, так как ни тот, ни другой 
    //не являются родительскими классами для этого. Но из A — есть.
    double health;

    void SetStr( String newstr ) {
        internalstr = newstr;
    }

    void ResetAll( void ) {
        a = b = 0;
        health = 0.0;
        internalstr = "";
    }
}
```

Для примеров использования полиморфизма и инкапсуляции см. "1.13. Виртуальные методы, абстрактные классы/методы".



## Области видимости

Распространяются на методы и поля данных внутри класса. Отвечают за то, откуда логически можно будет обращаться к переменным и вызывать методы. При наследовании области видимости не изменяются.

[Укороченный материал по теме на Википедии](https://ru.wikipedia.org/wiki/%D0%9E%D0%B1%D0%BB%D0%B0%D1%81%D1%82%D1%8C_%D0%B2%D0%B8%D0%B4%D0%B8%D0%BC%D0%BE%D1%81%D1%82%D0%B8#%D0%A2%D0%B8%D0%BF%D1%8B_%D0%BE%D0%B1%D0%BB%D0%B0%D1%81%D1%82%D0%B8_%D0%B2%D0%B8%D0%B4%D0%B8%D0%BC%D0%BE%D1%81%D1%82%D0%B8).

### Public (публичный)

Поля и методы класса, объявленные с этой областью видимости, доступны всем и вся из всех файлов.

Специального ключевого слова в ZScript не имеет — `public` применяется по умолчанию ко всему, если не указано `protected` или `private`.

В примере ниже переменная `v`, функция `SetAtLeastEleven()` и функция `GetVarFromMyClass()` имеют такую открытую всем область видимости — по этой причине можно обращаться к полю `v` из-под другого класса. К слову, встроенная функция `max()` тоже публичная.
```Csharp
class MyClass {
	int v;

	void SetAtLeastEleven( int input ) {
		v = max( 11, input );
	}
}

class OtherClass {
	int GetVarFromMyClass( void ) {
		MyClass m = GetMyClass();

		return m.v; // Обращение к "MyClass::v" возможно.
	}
}
```

### Protected (защищённый)

Метод или переменная будет доступна только для этого класса и его наследников. Используется, если нужно разграничить доступ ко внутренним полям, чтобы компилятор запрещал "снаружи" обращаться к ним, вызывать и менять их.

Ключевое слово — `protected`. Количество дочерних классов и длина цепи наследования не играет роли, из нескольких наследников `protected`-поле доступно каждому из них.

В примере ниже `SetFirstToSecond()` может обратиться и к переменной `ca.first`, и к переменной `ca.second` только потому, что `HeirClassB` наследован от `HeirClassA` (в котором есть `second`), который наследован от `MyClass` (в котором есть `first`). При этом, разумеется, и `first`, и `second` есть в экземплярах самого `HeirClassB`.
```Csharp
class MyClass {
	protected int first;
}

class HeirClassA: MyClass {
	protected int second;
}

class HeirClassB: HeirClassA {
	HeirClassA ca;

	protected void SetCAFirstToSecond( void ) {
		// Если бы здесь класс не наследовался от "HeirClassA" (или уже его
		// наследников), то даже с валидным `ca` компилятор бы выдал ошибку.
		ca.first = ca.second;
	}
}
```

_На старых версиях движка (примерно до GZDoom 3.4.0) полям данных нельзя было назначать область видимости, они всегда обязаны были быть `public`._

### Private (приватый)

Метод или переменная доступны для объектов исключительно этого самого класса, и даже при наследовании "исчезает" из описания дочернего класса. Используется для наиболее жёсткого разграничения прав доступа — например, если неаккуратное изменение снаружи может привести к поломке хрупкой структуры внутри. На этом построен так называемый механизм "сеттеров"-"геттеров" — публичных функций в этом же классе, которые определяют правильную работу со внутренним полем и, соответственно, корректно обрабатывают все случаи.

Ключевое слово — `private`.

В примере ниже показан сеттер, сообщающий об изменении и устанавливающий новое значение по условию, а также простой геттер. При этом к "сырому" `v` доступа снаружи нет, всё в любом случае обработается через `SetV()` и `GetV()`!
```Csharp
class MyClass {
	private int v;

	void SetV( int input ) {
		console.printf( "Old value %i, new input %i.", v, input );

		if ( input > 10 && input < 20 )
			v = -input;
		else
			v = input * 2;
	}

	int GetV( void ) {
		return v;
	}
}
```

_На старых версиях движка (примерно до GZDoom 3.4.0) полям данных нельзя было назначать область видимости, они всегда обязаны были быть `public`._


### Общий пример

Из-за использования слова "`protected`" для одного строкового поля в классе "`A`" пример не будет работать на очень старых версиях движка.

```Csharp
class A {
    int a, b;
    protected String internalstr;

    private void SetStr( String newstr ) {
        internalstr = newstr;
    }

    void PrintStr( void ) {
        console.printf( internalstr );

        SetStr( "Printed '" .. internalstr .. "'." ); // Отсюда метод без труда вызывается, класс тот же самый.
    }

    protected int sum3( int c ) {
        SetStr( "Called sum3( " .. c .. " )." );

        return a + b + c;
    }
}

class B: A {
    int SomeExtraSum( int d ) {
        if ( d > 0 )
            return sum3( d );
        else
            return -d;
    }

    void Init( void ) {
        SetStr( "Hello world!" ); // Компилятор выдаст ошибку: приватный метод "SetStr()" недоступен даже из-под наследника.

        internalstr = "Hello world!"; // А так можно, ибо поле обявлено как "protected".
    }
}

class SomeOtherClass {
    A obja;

    int TryToGetSum3( void ) {
        // Ошибка: "obja.sum3()" является protected-методом, для чужих оно недоступно.
        return ( ( obja != NULL )? obja.sum3( 3 ) : -1 );
    }

    int TryToGetInt( void ) {
        // Поле "int a" публично, ошибки не будет.
        return ( ( obja != NULL )? obja.a : -1 );
    }
}
```

## Статические методы

Иногда требуется написать код не к какому-то конкретному экземпляру класса, а к самому классу. Например, когда суть метода относится в целом к классу. Упоминавшийся ранее "`Actor.Spawn()`" (см. 1.11) тому пример — у нас может и не быть ни одного актора на уровне, но создавать-то их как-то необходимо.

В объявлении такого метода должно присутствовать ключевое слово `static`.

```CPP
class Math {
    static double pow( double value, double power ) {
    	if ( power == 0.0 || value == 1.0 )
    		return 1.0;
    	if ( power == 1.0 )
    		return value;

    	return exp( power * log( value ) );
    }
    
    static double haversin( double fita ) {
    	return ( 1.0 - cos( fita ) ) * 0.5;
    }
}

// <...>
console.printf( "2^5: " .. Math.pow( 2.0, 5.0 ) );

console.printf( "3.17^6.3: " .. Math.pow( 3.17, 6.3 ) );

console.printf( "haversine( 5 ): " .. Math.haversin( 5 ) );
```
